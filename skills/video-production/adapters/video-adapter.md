# Video Adapter

At project start, declare the provider or platform and access route, exact model/version, target resolution, available duration options and aspect ratios, first/end/transition-frame support, multimodal reference limits, multi-shot support, native audio capabilities, timing syntax, asset-binding syntax, persistent-context behavior, and known failures. Capture evidence from the actual execution surface; do not assume a wrapper exposes every official model feature. State which output settings are request parameters rather than prompt text. Unless persistent context is proven, treat every Clip request as independent and deliver its global values plus exact applicable identity anchors in that call.

Compile a Clip-first Video Prompt only after the required baseline, output specification, and cost Gate are approved. Validate the internal plan at 0.1-second precision; do not claim deterministic frame-level compliance. Background music is excluded from every Video Prompt. Native speech direction and voice invariants are included only when this Adapter's selected route actually generates speech.

When native audio is available, explicitly choose `native_speech` or `silent` from the project goal instead of defaulting to silence. If the user prioritizes reducing post-production, prefer native locked dialogue with synchronized ambience/Foley/SFX, omit narration unless assigned by the frozen Script, and continue to exclude BGM. For recurring speakers, compile one stable approved voice label per character and repeat it verbatim in every applicable Clip. If this Adapter supports audio references, bind the same approved per-character samples by explicit role on every applicable request after rights/consent review. Neither text labels nor audio references guarantee deterministic voice identity, so require per-Clip QA for exact words, speaker attribution, voice continuity, lip sync, distortion, and mix balance; keep passing native audio and route a failed audio layer to independent replacement or human decision rather than automatically regenerating the video.

For `external_prompt_only`, user evidence may establish that Updream's Seedance 2.5 entry supports complete generation, timestamp editing, extension, and image/video/audio references. Treat those as the current operation/reference evidence only; resolution, aspect ratio, duration choices, input limits, and UI parameter names remain `UNKNOWN` until observed on the real surface. The Adapter compiles local instructions only and never connects to Updream/Seedance, submits a task, handles billing, or polls generation status.
