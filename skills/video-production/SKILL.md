# Video Production

Turn a frozen Script plus ADP v1.2, ready Style Profile references, and semantic template bindings into a production manifest. Preserve all semantic locks. This Skill owns production decisions; it does not revise Topic, Script, or ADP intent.

## Staged delivery boundary

Read [Staged Approval Gates](../workflow-controller/contracts/staged-approval-gates.md) before
running. After Stage 0 (`确认第1点`), prepare the visual test package and output exactly one
Global visual DNA plus three image prompts: `主角`, `场景`, and `Key Frame`. Stop for Stage 1
(`确认第2点`). Only then may this Skill render the complete production materials and project them
to Notion. Stage 1 approval is not approval for any paid generation call.

For `workflow_mode: external_prompt_only`, use the Fast Path defined by the Controller, Production Router, Asset Reference Router, and Clip Prompt Compiler. It is limited to a local Seedance Prompt Package for manual Updream use. Do not require the managed Script Architecture, three Visual Tests, Full Production, Manifest, Notion, or Cost Gate; do not connect to a provider or generate media. Return after one bounded Feed-first preflight with `prompt_ready_for_external_use`, `blocked`, or `human_review`. A later, separately activated External Result Review reads final-file technical facts first and may do semantic QA only after confirming the originating Fast Path package, actual request parameters, and reference roles; it never invokes managed media intake or writes managed state.

## Required input and authority

Read [input contract](contracts/input-contract.md) and [production manifest](contracts/production-manifest.md) first. When voice production is enabled, also read the [Audio Production Contract](contracts/audio-production-contract.md) and [Audio Adapter](adapters/audio-adapter.md). If the Controller selects Seed Audio v3, additionally read the [Seed Audio v3 Adapter](adapters/seed-audio-v3-adapter.md). When automatic named-voice selection is requested, run `scripts/select-doubao-voices.ps1` against structured Character & Voice Bible requirements, return at most three candidates per role, and keep `selected_voice` null until account availability and human approval are evidenced. Do not substitute Seed Audio v3 full-scene generation for a named `voice_type` route. The order of authority is: frozen Script and ADP semantic locks, approved Visual Baseline, current Adapter capability, then runtime design. A source Style Profile must be `ready`; its legacy model or prompt rules never override this Skill.

Do not require a Video Adapter intake before Scene, Clip, or Prompt planning. Use execution facts the user has already supplied and let unknown platform controls remain unresolved during planning. Confirm only the parameters needed for the actual request in its Cost Gate or call package immediately before submission; a model's official capability does not prove that a third-party platform exposes the same control.

When a generated production asset must be a transparent PNG, route the approved image request through the existing ChatGPT Web conversation for the current Work/Codex task. Do not assume cross-surface attachment sync, open a new conversation, or switch to another image route when that conversation is unavailable; report the blocker and wait. The image still requires its existing Visual Baseline and exact Cost Gate. For small compatible VOX elements, use the smallest sufficient `2x2` or `3x3` transparent atlas, one complete element per cell with wide gutters and safe margins, then crop locally. Verify real saved-file Alpha before cropping and intake; only the resulting independently checked RGBA PNGs may bind to Remotion, never the atlas itself.

When the selected route is the optional local `whiteboard_animator` Renderer, read the [Whiteboard Animator Adapter](../../video-production/adapters/whiteboard-animator-adapter.md) and [Render Contract](../../video-production/contracts/whiteboard-animator-render-contract.md). Its intake records `local_cli`, exact Renderer/runtime versions, a checksum-bound source image, an optional checksum-bound RGBA tip with rights evidence and explicit normalized `tip_anchor`, `native_audio: none`, and this video's confirmed output specification; it does not invent provider/model fields. Run input-suitability preflight before render. Full-frame connected illustrations without usable structured line art/layers are `unsupported` or `human_review`, not a successful reveal. `aspect_ratio`, `resolution`, `width_px`, and `height_px` remain `UNKNOWN` until this video confirms them and then block a formal Job if unresolved. The local CPU execution needs no media-generation Cost Gate, while any paid source-image generation still follows the existing Visual Baseline and image Cost Gate. This Adapter is managed-production only and never turns `external_prompt_only` into a local-execution shortcut.

The accepted gyroscope v2 behavior remains the flat-image implementation baseline. Explicit complex-scene contract `1.1` may use `stacked_layer_object_complete_reveal`: ordinary layers run supplied `line_then_fill`, authored shadows or other color-only layers run line-free `direct_fill`, phase timing follows draw order, and every frame composites by independent z-order. Never infer pixels hidden by foreground objects, and do not use the rejected v3 hidden-underlay method.

Contract `1.2` retains the same Adapter/Renderer and adds adaptive source and timing planning. Author new sources at 4x output geometry with alpha-aware area downsampling. Use `render_route: auto` to select `flat_auto` only for sparse, separable, low-text material; multi-line text, cards, overlap/z-order, or complex line/fill relationships require `structured_semantic` with explicit RGBA layers and text regions in top-to-bottom, left-to-right reading order. Require the preflight route evidence, `whiteboard_source_plan`, and frame-conserving timing plan. Automatic whiteboard pace selects only `calm`, `normal`, or `energetic` from skeleton length, fill area, pen lifts, text burden, and available frames; insufficient duration returns `human_review` and a reduction/split reason. Stroke/fill timing maps remain independent, and a tip-enabled render is technically eligible only when `post_snap_outside_count` is zero.

Contract `1.3` keeps the same Renderer and projects any registry-`ready` Style Profile through the upstream deterministic `whiteboard_style_slice`; the Renderer never reads or interprets the Profile. The slice records every accepted, transformed, dropped, and blocked field plus source/profile hashes. Only text, cards, icons, arrows, geometry, and deterministic flat assets may compile locally at 4x; complex characters or illustrations stop at source brief / prompt-package-ready and retain existing rights, Visual Baseline, and Cost Gate boundaries. A new style-slice, source-template, Renderer behavior, route, geometry/fps, or tip/anchor fingerprint requires one risk-selected 3–6 second final-resolution Pilot. Propagation is blocked until existing Controller/Review evidence records human acceptance; an exact accepted fingerprint may be reused.

New character Jobs must bind checksum-bound part, outline, and detail masks and use `head_body_upper_arms_forearms_hands_thighs_lower_legs_feet`; the fixed anatomical order is head, body, upper arms/upper forelimbs, forearms/lower forelimbs, hands/front paws, thighs/upper hindlimbs, lower legs/lower hindlimbs, then feet/hind paws. Within each part, draw the outline before interior details. Do not infer anatomy or interior meaning from connectivity or position. `head_body_hands_feet` and `head_first` remain compatibility input only.

Before formal rendering, use the manifest-declared `whiteboard-production-cli.ps1` to emit `whiteboard_render_plan` from active draw, hold, exact frames, pixel-frames, layers/objects/text, skeleton, fill area, pen lifts, and an evidenced local benchmark. Long static hold alone does not force a split. `segmented_render` cuts only after complete semantic object groups; never within a text row, continuous stroke, line-to-fill pair, or semantic action. Each immutable segment Job runs and passes technical checks before the next starts. `continuous_canvas` uses non-overlapping global frame windows and hides the tip at the boundary; `board_cut` is explicit. Merge validates exact frames, boundaries, canvas state, full decode, and SHA-256, and still returns only `success_pending_human_review`.

## Workflow

1. Use the [production router](modules/production-router.md) to reject incomplete or unapproved input. After Stage 1 approval, plan Scene, Clip, Shot, and Camera Beat separately using [scene-clip planner](modules/scene-clip-planner.md) and [pace router](modules/pace-router.md).
   When the ready VOX Profile selects Remotion local assembly, read approved Shot intent and assets, persist key layouts and independent layer geometry/anchors, bind the confirmed final narration, schedule camera/layer/caption/SFX events in integer frames, render locally, and route the result to existing `production_qa`. Do not require a generative Video Prompt, provider call, or 6–14 second Clip default for that local unit; hybrid units that actually generate video retain those controls. Static, dynamic, and compound motion are peer options selected by intent, with one primary attention target at a time rather than one action per Shot.
2. Run the existing [Storyboard and Keyframe Planner](modules/storyboard-keyframe-planner.md). Record an evidenced skip only for low-risk/no-trigger work. For retained work, compile one risk-selected Contact Sheet, stop at its separate Cost Gate, and require immutable real-media evidence plus a current `previsualization_storyboard` Review Result before advancing. A Fixture or prompt preview never becomes READY.
3. Create only the 3–5 LookDev anchors required by the ADP. Follow [LookDev calibration](modules/lookdev-calibration.md). Do not batch-generate assets before each relevant Style, character direction, and Domain has AI QA plus human approval.
4. Bind each approved Style Profile, executable prompt, and generated image as one Visual Baseline. If a Domain fails, block only that Domain. Storyboard media remains previsualization and cannot satisfy this baseline.
5. Compile assets and references with [asset prompt compiler](modules/asset-prompt-compiler.md), [asset reference router](modules/asset-reference-router.md), and the [Executable Prompt Contract](contracts/executable-prompt-contract.md). Use only the type-specific template that applies. For an approved VOX transparent-atlas handoff, run `scripts/split-transparent-atlas.ps1` only on a saved PNG with verified real Alpha; the wrapper resolves the approved Pillow runtime and invokes the Python named crop, which rejects opaque, empty, edge-contact, non-empty-unused-cell, and unapproved-overwrite inputs without removing backgrounds or inventing outline colors. Prompts may be locally previewed, but real calls require a user-approved cost Gate.
6. Before compiling a complete Clip Prompt, validate the `story_change_arc -> performance_plan -> clip_performance_binding` reference chain and run the deterministic portion of [Scene Continuity Gate](modules/scene-continuity-gate.md) and [Video Prompt Feasibility Gate](modules/prompt-feasibility-gate.md). If those pass, run the required bounded semantic preflight as one evaluator call that includes the existing physical/literalization risks, [Prompt Story Function Conformance](modules/prompt-story-function-review.md), and Duration Fit. Duration Fit judges required visible state changes and ending hold at the current duration, maps high-confidence risk through existing `timing_failure`, and never counts actions, dictates a fixed duration, or auto-splits Clips. Persist the revision-bound managed result using [Review Result v2.1](contracts/review-result-contract.md) in `production_manifest.qa.results`. Only an evidence-backed high-confidence pass may render the self-contained six-module prompt and recommend entry to the separate Cost Gate; missing/unknown review stays withheld, and semantic impact routes to human review. Record actual generated state only in the [continuity ledger](modules/continuity-ledger.md).
   For `reference_video_structural_remake`, also bind the current `constraint_hash`, each critical
   `reference_fidelity_trace`, and one-reference-one-role assets into existing Clip/asset records.
   Keep source evidence time, target plan time, and observed media time distinct. Reference units are
   not converted one-for-one into Clips merely to match a default Adapter duration.
7. Route evidence-bound Production QA through [QA and Targeted Retry](modules/qa-retry.md). Reuse Execution State to accept/stop, edit/reuse, request the separate regeneration Cost Gate, or escalate to human review; do not create a Regeneration Gate or second retry counter. For a bound Final Master, the existing `production_qa` owner may run the deterministic local technical probe only: compare final video/audio checksum bindings, actual audio-stream duration, delivery resolution/frame rate/sample rate, audio-track presence, and first/last decodability against the declared tolerance. It returns the existing Evaluator Result v1.1 and never creates a Final Cut Review, Gate, Manifest subtree, or semantic/human acceptance claim.
8. When `audio_production.enabled=true`, use the [audio production module](modules/audio-production.md) to turn locked narration/dialogue and ADP voice direction into planned voice requests and an Audio Timeline. A generated file and measured duration are required before an entry is assembly-ready.
9. When `bgm_production.enabled=true`, read the [BGM Production Contract](contracts/bgm-production-contract.md), compile the ADP Music Brief and derived prompt into one independent request, then route it through the selected [BGM Adapter](adapters/bgm-adapter.md). ElevenLabs Music v2 is configured as a guarded provider path; it remains dry-run until the exact BGM cost Gate and API credential are present.
10. After Stage 1 approval, render the full production package from the manifest, preserve all independent media cost Gates, and only then perform the scoped Notion projection with idempotency and read-back verification.
11. If the approved ADP selects `whiteboard_animator`, first bind the source image and optional tip asset through existing asset intake and rights evidence, compile one revision-bound explicit integer-frame Job, and run the mandatory suitability preflight. Stop on `unsupported` or `human_review`; never infer hidden structure. For 1.3, also bind the derived style slice, Pilot fingerprint decision, and benchmark-backed render plan before formal propagation. Render sequential immutable Jobs only; retain passed segments and stop downstream on failure. Only a supported preflight may route to formal local execution. The Renderer and final merge return execution facts and `success_pending_human_review` only. Bind a successful silent H.264 through existing media intake and `qa.results`, and route any retry through existing Execution State.

## Non-negotiable boundaries

- Clip-first: Beat, Scene, Clip, Shot, and Camera Beat are different units. Default first-pass generative Clips are 6–14 seconds unless the Adapter proves another stable limit. Local Remotion assembly Shots follow the confirmed narration/editorial timeline and are not generation calls.
- VOX Remotion local assembly does not impose default static camera, micro-push amplitude, one action per Shot, fixed layer count, universal back-row opacity/floating motion/shared Y coordinate, a closed six-effect vocabulary, mandatory original-poster restoration, or end-of-Shot global freeze. Preserve readable intervals, identity/text/fact locks, spatial relationships, paper medium, asset coverage, and fixed-seed determinism. A stronger camera move, controlled perspective, local shake, fold/rotate/deform, or dissolve is assessed by intent and risk rather than rejected by category.
- `expected_end_state` is inherited from the ADP; `actual_end_state` is written only after inspecting a real generated Clip.
- BGM, voice, Foley, and SFX are separate production assets; never put BGM in a Video Clip Prompt.
- When the selected Video Adapter supports native audio and the user prioritizes less post-production, prefer native locked dialogue plus synchronized ambience/Foley/SFX over defaulting the Clip to silent. Include narration only when the frozen Script assigns it, and continue to exclude BGM. For recurring speakers, repeat the same approved voice labels in every independent Clip and, when the Adapter supports it and rights are verified, bind the same approved per-character audio references. Treat voice identity as probabilistic: QA every Clip for exact text, speaker attribution, timbre/age/accent/prosody continuity, lip sync, distortion, and balance; retain passing native audio, otherwise route only the failed audio layer to independent replacement or human decision.
- Do not rely on cross-request model memory. Every generation request must carry its applicable global values and exact frozen identity anchors in the prompt or Adapter request parameters.
- For a successor Clip with an accepted, readable predecessor, compile a predecessor-endpoint continuity binding before its prompt: use the predecessor's terminal frame as the Adapter's first-frame input when supported, otherwise as a reference image with the explicit role `predecessor_endpoint_continuity`. Derive and lock the cut-boundary pose (including screen-side and left/right hand or prop contact), screen direction, subject/prop placement, key/fill direction, white balance, exposure, contrast, saturation, palette, and warm/cool relationship. Preserve these through the opening hold only; later changes must be explicit timeline actions. A prompt-only assertion cannot claim that an unbound predecessor is preserved.
- If the Adapter has neither first-frame nor usable reference-image input, keep pixel-level start-state and grade continuity `UNKNOWN`; request an approved Resume Frame or a deliberate-cut decision rather than fabricating continuity. This extends the existing Continuity Ledger and Adapter binding only; it does not create another state store or approval Gate.
- `duration_seconds`, `aspect_ratio`, `resolution`, and `native_audio_mode` must be reviewable per Clip; unresolved required output parameters block generation.
- Voice Profile selects an approved provider voice and delivery constraints; it is not permission to clone, imitate, or synthesize a real person's voice without verified rights.
- `production_manifest.json` is the machine source of truth. `Production_Package.md` is a review projection only. Notion, if used later, is only a UI.
- Do not create a Creative Handoff Snapshot, Storyboard-specific state machine, Review core, retry ledger, or actual-state store. `READY / REVISE` are human projections of Review Result plus Execution State.
- A full production package or Notion write is blocked until the Stage 1 visual-test confirmation is recorded. The first review package must never be replaced by a full production dump.
- Notion projection may reuse only the existing `视频项目`, `制作资产`, and `Clips` structures. Write a local pending state first, use an idempotency key, read back page body/relations/formatting, and retain `DEGRADED`/retryable state on failure.
- When projecting production data to Notion, a project prompt page must filter every linked `制作资产` and `Clips` view by the exact `项目` relation page ID. Never expose a shared unfiltered view under a project-specific prompt page.
- A Notion `Video Prompt` field is the copy-ready executable prompt only. Keep status, QA findings, cost gates, acceptance notes, and "see another document" instructions in their dedicated properties or page body; never replace the prompt with those notes.
- A fixture, local compiler output, or AI QA cannot satisfy human approval or prove media quality.
- Review Result eligibility is not paid-generation approval. A Review fixture cannot recommend entry to the real Cost Gate, and a target/dependency hash change invalidates its prior decision.
- Before any credit-consuming image, video, voice, SFX, or BGM request, present the exact minimum asset set, model, quantity, estimated cost, stopping condition, and obtain explicit user approval. Provider connection approval is not generation approval.

## Controller return

Use this Skill directly for one bounded Prompt, media-intake, real-media QA, continuity, audio, or packaging subtask selected within existing Gates. Any Manifest/Prompt/Review/media/QA/Continuity change must populate the logical `controller_return` envelope defined by Workflow Controller. Include exact artifact refs and SHA-256 where observed, Review/Continuity refs, approval state, unresolved evidence, external-action boundary, and one recommended next action. Follow the Controller's user-facing rendering rule: do not append raw `controller_return` YAML/JSON unless the user explicitly requests machine-readable or debug details, or a destination tool requires it. Report new media as planned versus observed; intake must bind target/revision/checksum without creating `actual_end_state`, QA PASS, human approval, or selected-media status. Production QA may recommend exactly one of accept/stop, edit/reuse, separate regeneration Cost Gate, or human decision. Stop after the envelope and never generate the next Clip or invoke another Specialist. If reliable Controller re-entry is unavailable, use `awaiting_controller_resume`.
