# Production Router

For `workflow_mode: external_prompt_only`, validate the selected S1–S4 strategy and any execution facts the user supplied. This route owns only operation selection, reference binding, compact Prompt Package compilation, and one bounded Feed-first preflight. It does not create a Manifest, visual-test package, LookDev, Storyboard, Keyframe, Clip plan, Notion projection, Cost Gate, provider call, or generated-media status. S1/S2 with complete user content may proceed directly; route only missing topic, script/fact, or compact audiovisual direction to the existing owner. S4 names at most three primary precision targets, delegates camera variation/transitions/micro-performance/visual surprise to the model, and prefers one supported story unit over automatic shot splitting. A PASS returns `prompt_ready_for_external_use` to the Controller; any semantic change, unknown factual claim, low confidence, or contradictory execution facts returns `blocked` or `human_review`.

1. Validate the Input Contract and confirm the staged approval state. Without Stage 0 approval, block before visual output; without Stage 1 approval, block before the full package and any Notion write. Before Clip compilation, run the deterministic Scene Continuity and Feasibility gates and preserve open semantic states.
2. Resolve only ready Style Profiles and record their registry IDs and source provenance.
3. Load Adapter capabilities without inheriting legacy profile production syntax.
4. After Stage 0 approval, compile the minimum visual test package: Global visual DNA plus `主角`, `场景`, and `Key Frame` image prompts. Stop for Stage 1 confirmation.
5. After Stage 1 approval, freeze `semantic_locks` and build Scene and Clip plans. Run the existing Storyboard Planner: low-risk/no-trigger cases may record an evidenced skip; retained cases compile one risk-selected Contact Sheet plan and stop at a separate Storyboard Cost Gate.
6. A retained Storyboard blocks downstream generation until a real asset revision/checksum and current Review Result v2.1 reference exist. Fixture output and prompt preview remain planned and never become READY. Storyboard PASS advances only to Prompt planning.
7. Create the ADP-defined 3–5 LookDev anchors. Set the relevant Gate to `awaiting_user_approval` before every external call and compile only the minimum approved Gate set.
8. Route generated results through QA, continuity, and the existing accept/edit/request-regeneration-Cost-Gate/human policy. Project a review-only `Production_Package.md` from the manifest, then project to Notion only after Stage 1 confirmation.

When any prerequisite is missing, return a specific block reason; never silently substitute a Fixture or a planned state for evidence. A v1.5 or v1.6 manifest is read-only migration input; a v1.7 revision is written alongside it.

For registry-ready `vox_transcript_driven_handmade_collage` with `assembly_engine: remotion`, route approved assets and intent records through the existing local-assembly branch: read semantic locks and asset/rights evidence, persist key layout states, bind the confirmed final narration, schedule camera/layer/caption/SFX events, render locally, then enter existing `production_qa`. This branch does not require a generative Video Clip Prompt, provider submission, or the 6–14 second generative Clip default. In a hybrid project, only the units that actually invoke a generative video Adapter keep those requirements. The exemption never relaxes Script/ADP semantics, Visual Baselines for generated assets, rights/provenance, staged approval, paid-call Cost Gates, media intake, or final QA; it does not apply to `whiteboard_animator` or `external_prompt_only`.

For `whiteboard_animator` contract 1.2, request `render_route: auto` unless an approved source package fixes `flat_auto` or `structured_semantic`. Sparse, separable, low-text sources may use `flat_auto`; multi-line text, cards, overlap/z-order, and complex line/fill relationships require `structured_semantic` with explicit RGBA layers and text regions. Record route evidence, confidence, source plan, timing plan, and blockers. Never force a complex flat image through render.

For contract 1.3, resolve a registry-`ready` Style Profile to one deterministic `whiteboard_style_slice` before source compilation; do not pass the Profile to the Renderer. Record accept/transform/drop/block decisions and stop on unknown critical visual fields. Bind the complete quality-affecting Pilot fingerprint and reuse existing Controller/Review evidence: a missing human acceptance blocks propagation, while an exact accepted fingerprint may be reused. Before formal render, require a benchmark-backed `whiteboard_render_plan`. Route only `single_render`, safe semantic `segmented_render`, or `human_review`; do not split a text row, continuous stroke, line-to-fill pair, or semantic action.
